# Node 子进程识别修复与发布验证 · 2026-10-29

本轮发布 Codex 0.1.2、DSH 0.1.3。两个宿主继续复用同一个 Go 核心；DSH 接入代码未改。

## 修复范围

- 不再把普通 Node 脚本、查询、测试、模块读取和 Shell 包装一律拒绝。
- 对可识别源码中的 `child_process` 调用按实际命令检查；直接、变量／解构导入、动态导入和已知 heredoc 均纳入。
- `NODE_OPTIONS` 不再误拦未运行 Node 的 Git 查询或未调用函数；影响内联代码检查的预加载仍保守拒绝。
- 不新增直接 `git commit` 授权或全面 Gitee 写入封锁；脚本内部、动态／编码程序及未知工具仍是识别边界。

## 本轮证据

- 当前源码根包全量 `go test . -count=1` 通过。
- Node 目标测试包含直接／解构导入的 `child_process`、动态导入、heredoc、Shell 包装及误拦反例；真实 Node 配合假 Git 确认受保护推送未执行。
- 五个平台程序均从当前源码重建；Codex 六个 ZIP、DSH 三个单平台包和 npm 通用包已生成并核对内容、权限与程序字节。
- macOS ARM64 npm 包测试 3/3 通过：文件白名单、精确程序、真实 CLI 安装／重复安装和拒绝→授权→单次执行→再次拒绝。
- macOS ARM64 单平台 ZIP 原生启动与授权测试通过。
- macOS ARM64 真实 Codex 隔离宿主测试通过：MCP 创建拒绝、单次消费、失败不复用、Shell 创建拦截；真实 GitHub 写入与付费模型调用均为零。

## 边界

- macOS Intel、Linux x64 和 Windows x64 仅完成构建与包结构／一致性检查，本轮未做原生运行。
- Linux ARM64 的补充结果以实际远端验收为准，不沿用历史记录代替。
- 发布后的 npm 精确版本、GitHub tag 与附件回读另按发布流程完成。
